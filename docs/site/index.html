THE STORY

It started with Mayordomo. It should not end there.

The first consumer is Mayordomo — El juego que no es un juego. Building its digital version forces the engine to solve real problems: turns, choices, state, deterministic randomness, cards, money, replay, multiplayer and recovery.

Instead of letting those concerns fuse into one branded application, the reusable mechanics live here. Mayordomo's rules, Studio, official content and branded clients live privately in Mayordomo.Game. Product knows engine. Engine never knows product.

ARCHITECTURE

Reusable because the dependency points one way.

Deterministic core

Same initial state, seed and command stream means the same events and final state.

Headless first

No browser, Unity, XAML, network, database or cloud service is required to execute game behavior.

Server authoritative

Clients ask. The authoritative engine validates and produces the resulting state transition.

Product agnostic

If a concept needs Mayordomo vocabulary to explain it, it probably belongs in Mayordomo.Game.

SMALL & FAST BY CONTRACT

Performance claims should survive a build.

We publish budgets first and measurements second. CI enforces the footprint ceiling today; reproducible runtime benchmarks become gates as soon as the walking skeleton has meaningful work to measure.
